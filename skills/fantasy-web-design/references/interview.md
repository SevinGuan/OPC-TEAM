# 分层引导访谈流程

## 目的

帮助"有审美但不会提词"的用户，通过对话逐步锁定设计方向。访谈的本质是**产品发现**，不是参数收集——先了解用户要做一件什么事，再谈视觉。

## 第零步：分流

开场问：

> 「开始之前，用你自己的话说说：你想做个什么样的网页？随便聊，不用任何专业词。」

判断规则：
- 表达含糊、用比喻、口语化、说"我也说不清" → **小白路径**
- 出现"暗色主题""栅格""响应式""组件库"等术语 → **专业路径**
- 不确定时，直接问一句：「你平时自己写前端代码吗？」写 → 专业路径；不写/很少 → 小白路径

用户在任意阶段可主动切换路径，切换时保留已收集的答案，只换提问方式。

## 小白路径：产品发现式五问（全程零术语）

### 第一问：做什么（定位）
> 「你最近想做一件什么事？为什么想做它？」

要挖出：网站主题、目的、内容是什么。用户说得散没关系，帮他把要点复述确认。

### 第二问：给谁用（受众与场景）
> 「做完之后，谁会打开它？他打开的时候正在干嘛——早上拿着手机刷，还是坐在电脑前认真看？」

要挖出：目标受众、使用场景、主要设备（手机/桌面）、单次使用时长（决定信息密度）。

### 第三问：什么性格（情绪基调）
> 「如果这个网站是一个人推门进来，你希望他是什么样的人？」

提供选项（用户也可自己描述，对照 persona-token-map.md 找最近似的）：
- 热情的销售高手——一进门就拉着你说个不停
- 冷静的教授——慢条斯理，一句是一句
- 犀利的操盘手——快、准、狠，不多说一个字
- 温和的图书管理员——安静、体贴、帮你把东西都整理好
- 前卫的艺术家——一进来整个房间的气氛都变了
- 靠谱的工程师——严谨、精密、每个细节都有理由

### 第四问：热闹还是安静（密度与动效）
> 「你希望它更像哪种地方：安静的书店、热闹的夜市、还是精密的驾驶舱？」

可追加：「页面上的东西，你希望是一屏塞得满满的，还是一件事一件事慢慢讲？」

### 第五问：有没有对的感觉（锚定参照物）
> 「有没有哪个网站、App、杂志，甚至一家店，你看过觉得'就是这个感觉'？发我链接或截图都行。说不出来也没关系。」

拿到参照物后，分析其视觉特征（配色、密度、字体气质、动效），作为最高权重的风格依据。

### 收尾：确认与翻译
1. 用通俗语言复述收集到的画像：「好，我捋一下：你要做___，给___看，他打开时希望___，这个网站的性格是___，感觉像___。对吗？」
2. 后台加载 persona-token-map.md 翻译成设计 token
3. 向用户展示时翻译回通俗语言（用映射表的反向翻译栏）
4. 产出设计 brief（模板见文末），并从资源库匹配 3-5 个对口参考站点

## 专业路径：Token 对话（可谈细节）

直接进入设计参数层，逐项与用户对齐：

1. **明暗基调**：暗色终端 / 亮色克制 / 双模式
2. **信息密度**：高密度（一屏多列、小字号、紧凑行距）/ 中等分区 / 低密度留白
3. **字体系统**：中文（思源黑体/宋体、系统字体栈）/ 英文（衬线标题 vs 无衬线）/ 数字字体（等宽表格数字）
4. **组件与技术选型**：shadcn/ui 打底 + Tremor 数据可视化 + Magic UI 动效（参考 resources.md 模块二）
5. **动效强度**：无 → 微交互（hover/过渡 150-250ms）→ 数据动效（数字滚动）→ 大动效（进场动画）
6. **色彩规范**：主色、功能色（注意中国股市惯例：涨红跌绿）、中性色阶

同样以设计 brief 收尾。

## 设计 Brief 模板（两条路径统一出口）

```markdown
# 设计 Brief：[项目名]
最后更新：[日期]

## 项目画像
- 做什么：
- 给谁看 / 什么场景：
- 性格基调：
- 参照物：

## 设计 Token
- 色板：主色 ___ / 辅助色 ___ / 背景 ___ / 文字 ___ / 功能色 ___
- 字体：标题 ___ / 正文 ___ / 数字 ___
- 信息密度：___（一屏约 ___ 个信息块）
- 圆角：___px｜间距节奏：___px 基准
- 动效强度：___
- 图标风格：线性 / 填充 / 双色

## 对口参考（3-5 个）
- [站点名 + 一句话理由]

## 禁忌清单（去 AI 感 + 项目特殊要求）
- 见 anti-ai-style.md
- [项目自定义禁忌]
```
