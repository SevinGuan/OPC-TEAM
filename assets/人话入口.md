# 人话入口（创始人只说人话 → Agent 翻译成命令）

> 细则单一真相源。`SKILL.md` 的「创始人只说人话」表是本文件的摘要版；两者口径必须一致，改一处同步另一处。
> **宿主入口文件（`AGENTS.md` 等受控区块）里刻意没有本表副本，只有指针** —— 抄本会让「全新安装测试」变假阳性（不加载 Skill 也能照抄本干活），且抄本与包会口径漂移。原因见手册 §44.6。
> 适用范围：任何宿主、任何运行模式。翻译只允许「选命令 + 选参数」，**不允许**发明新命令、改写命令语义、跳过闸门。

## 1. 契约

**创始人不需要记任何命令。** 创始人用自然语言下达意图，Agent 负责翻译成**既有的确定性命令**（`scripts/opc.py`）并执行，执行完用自然语言回话。

三件事必须由 Agent 自己补齐，**不要反问创始人**（这些都能自己查到）：

| 要补的信息 | 从哪查 |
|---|---|
| 当前项目 | 话里带了项目名 → 带上 `--project`；否则用 `opc.config.json` 的 `active_project`（`handoff` / `advance` / `go` / `done` 自动取） |
| 当前阶段 / 接手岗位 / 待确认项 | `handoff` |
| role 名 | `handoff` 的接手岗位，或话里的角色词（「这一棒归 design 干」→ `--role design`） |

## 2. 映射表

| 创始人说 | Agent 跑 | 要点 |
|---|---|---|
| 「继续推进」「继续」「推进一棒」「同意」「可以交接了」 | `handoff` → 本棒已完成且**非闸门**：`go`；处于**闸门**（阶段 0 / 2 / 7）：**停下问创始人**「通过 / 驳回 / 需补充」，拿到明确结论才 `go --decision <结论>` | **§15.9：当前会话代为执行 `opc go`** —— 创始人在**哪个会话**里回「继续」，**那个会话**就推进，不要求切到 pm 会话；只推一棒、不跳步 |
| 「不同意」「驳回」「要改」「退回重做」「这版不行」 | `go --decision 驳回`（或 `需补充`） | **退回本阶段、游标不推进**，当前 role 补充后重报；闸门与非闸门都适用（v2.25） |
| 「<项目名> 继续推」 | `handoff --project <项目名>` → 同上 | 项目名认 4 种写法：短 ID `P001` / 目录名 `项目名`（同名 `-2`）/ 显示名 `项目名` / 老全名 `P001_项目名` |
| 「现在到哪一步了」「什么进度」 | `handoff`（或 `status`） | 回话要带：阶段 · 接手岗位 · 待确认项 |
| 「该派活给谁」「pm 看一下」「现在谁该干」 | `pm` | 只读统筹台账 +「现在该派谁」面板（接手岗位 × 岗位占用 × 闸门状态） |
| 「这次只让 X 干」「不用 Y」 | `triage --project <PXXX> --role <role> --involved yes\|no --assets <资产> --reason "<理由>"` | 派活清单 = 路由唯一真相源；解析失败显式报错，**不会偷偷按全量 9 步** |
| 「以 <role> 身份接棒」「这一棒归你」 | `role <role>` → `scaffold --role <role>` → 按该岗位卡干活 → `done --role <role>` | `role` 输出的就是该岗身份声明，**照抄进自己的上下文**，不必手写 |
| 「开工做设计」「准备做 X 了」 | `scaffold --role <role>` | 只生成自己那一份骨架（v2.18：立项只登记，不预生成空壳） |
| 「这棒干完了」「做完了」 | `done --role <role>` | 校验落盘 + 生成资产快照 + 发交接通知 |
| 「我要问你个事」「需要你拍板」「有问题要确认」 | `ask --role <role> --project <PXXX> --text "<问题>"` | **岗位自己主动问创始人**：用本岗身份在群里 @ 创始人（红点提醒）；**不推进游标、不产生资产批次** |
| 「可以沉淀知识了」 | `distill` → `link --version <V<N>> --role <role>` | **口语触发即执行**，不必再找谁审批 |
| 「资产台账」「产出可溯源吗」 | `assets [--role <role>]` | 版本 / 时间 / SHA256 / commit |
| 「有没有类似项目」「以前做过没」 | `similar --tags "..."` | 按标签检索历史落地物 URI |
| 「这个项目收尾」「结项」 | `close <项目> --link` | 收尾检查 + 简历回填 + 索引置已归档 |
| 「所有项目谁在忙」 | `queue` / `roster` | 只读流水线视图 / 岗位占用 |
| 「换行业」 | `profile` | 换 profile 不换架构 |

## 3. 三条硬边界（不得自行突破）

1. **闸门拍板权永远在创始人**（阶段 0 / 2 / 7）。`advance` 在闸门阶段一律拒绝。Agent 只能把「通过 / 驳回 / 需补充」摆给创始人，拿到**明确结论**才执行 `go --decision <结论>`。**「继续」不算闸门结论。**
2. **一次会话只绑定一个 role**（`single` 模式）。换角色必须开新会话：新会话第一句说「继续」或「以 <role> 身份接棒」即可接上。**同一会话里说「继续」不能变成下一个 role。**
3. **Agent 之间禁止在对话里互相唤醒；交接只走固定文件**（§15.3）。**但「门铃」不违反这条**：
   `opc new` / `opc go` / `opc advance` 由**脚本**自动在群里 @ 下一棒本人（宪法 §15.9.1），
   目的只是**把人叫醒**；下一棒仍须**自己** `opc claim` 领活，交接内容仍只走文件。
   流程推进权仍归创始人（`done` → 创始人说「继续」→ `advance`）—— 门铃不替代拍板。

## 4. 最容易搞混的三个命令

| 命令 | 谁发起 | 语义 | 闸门阶段 |
|---|---|---|---|
| `go --decision <结论>` | 创始人拍板 | 拍板留痕 + 推进一棒 | **允许**（但必须带明确结论） |
| `advance` | pm 代推 | 无拍板推进一棒 | **拒绝** |
| `pm` | 任何人 | 只读台账 + 派活决策面板 | 只是看 |

所以「继续」在闸门阶段的正确落点是：**问创始人**，不是 `advance`。

## 5. 翻译纪律

- **不发明命令**：只用上表与 `SKILL.md` 的 Commands 表里的命令。
- **不跳步**：`advance` 只推一棒；一次「继续」推一棒，要再推就等创始人再说。
- **不替创始人拍板**：闸门处停下问。
- **不反问能自己查到的东西**：项目、阶段、role、派活对象，先 `handoff` / `pm` 查。
- **改了命令语义就是 bug**：出现「我改了个 opc.py 让它更聪明」的想法，一律不做。

## 6. 三个真实例句

| 创始人说 | Agent 的动作序列 |
|---|---|
| 「继续推进」 | `handoff` → 若显示「等创始人拍板（阶段 1）」→ 回话「阶段 1 的 `1_MRD.md` 已就绪，是否通过？」→ 收到「通过」→ `go --decision 通过` → 回话「已推进到阶段 2，下一棒是 design」 |
| 「<项目名>继续推」 | `handoff --project <项目名>` → 同上（项目名替换为实际项目） |
| 「这一棒归 design 干」 | `role design` → 照抄身份声明 → `scaffold --role design` → 按 design 岗位卡干活 → `done --role design` |
