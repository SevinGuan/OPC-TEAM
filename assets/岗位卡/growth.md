## 10b 出海增长方法库（能力清单，非流程约束）

> 本节是**怎么做才有效**的口径库，供 §11.4 Step 3 / 3c / 8 引用。所有产出物都是**可照做的清单**，不是「要重视」。
> **执行边界**：策略、关键词表、文案与素材脚本、达人 brief、归因口径可由本岗产出；**付费投放、真人谈判付款、开发者账号与审核、社群即时沟通必须创始人下场**（本岗标注「需创始人执行」，不假装做完）。

### 订阅与收入指标（MRR 体系）
| 指标 | 定义 | 健康线 | 数据落点 |
|---|---|---|---|
| MRR | 当月订阅收入之和（年付/12，剔除一次性与税费） | — | RevenueCat / App Store Connect / Play Console |
| 五类变动 | New / Expansion / Contraction / Churn / Reactivation | — | 同上，按用户 ID 归因 |
| NDR（净收入留存） | (期初+扩张−收缩−流失)/期初 | **>100% 健康** | RevenueCat |
| Quick Ratio | (新+扩张)/(流失+收缩) | **>4 健康** | 同上 |
| 月流失率 / LTV / CAC 回收期 | LTV=ARPU/月流失率 | 流失<3% 优、<5% 及格；回收期<12 月 | 同上 |
| 试用转付费率 | trial→paid | 20–60% 常见区间 | 同上 |

> 出海特有：多币种、VAT/税率、**App Store 退款率**须单独看；禁止承诺具体转化率/复购率。

### ASO（应用商店搜索优化，出海第一战场）
- **词位**：Apple = 标题(30) + 副标题(30) + 关键词字段(100 字符，逗号分隔、不与标题重复)；Google Play = 标题(30) + 短描述(80) + 长描述（自然嵌入）
- **词来源**：App Store Connect 搜索词报告、AppTweak/Appfigures/Sensor Tower、竞品词、**各语言市场本地词根**（不是直译）
- **转化优先于排名**：图标 + 前两张截图 + 预览视频占约 70% 转化；用 Apple Product Page Optimization / Play 实验做 A/B
- **守护项**：评分 ≥4.5（在正向时刻弹评分）、崩溃率、更新频率；下载量↑→分类榜↑→自然曝光↑
- **交付物**：关键词表（词 / 月搜索量 / 竞争度 / 落位）+ 截图序列脚本 + 预览视频分镜 + What's New 文案

### Web SEO（独立站 / 落地页）
- 意图分类（信息 / 导航 / 商业 / 交易），**长尾低竞争优先**
- 一页一主词：标题 / H1 / 首段 / alt / 内链；**内容集群**（pillar + cluster 互指）
- 技术项：sitemap、canonical、**hreflang 多语言**、结构化数据（SoftwareApplication / FAQPage）、LCP < 2.5s
- 外链：AlternativeTo、Product Hunt、工具站收录、媒体报道
- **交付物**：词意图表 + 页面映射（一页一词）+ 技术检查清单

### GEO（生成式引擎优化，AI 搜索可见性）
- 目的：让内容被 ChatGPT / Perplexity / Google AI Overviews **引用**
- 做法：段落**直接给结论 + 数据 + 出处**（可摘取块）；FAQ/QA 结构化；`llms.txt`；**品牌实体一致**（Wikipedia/Wikidata/Crunchbase/G2 描述统一）；争取高权重源引用
- 衡量：在 Perplexity 提问品类问题，记录是否被点名（手工追踪表）
- **交付物**：可引用段落改造清单 + FAQ 结构化清单 + 实体描述统一对照表

### 达人 + 社媒（出海）
- 分层：**nano 1k–10k（CPM 低、信任高，冷启动最划算）** / micro / mid / macro / mega
- 找法：TikTok Creator Marketplace、YouTube BrandConnect、Aspire / Grin、Reddit·Discord 真实讨论
- 阶梯：**置换（免费会员）→ 佣金/CPA → 固定费**；专属折扣码 / UTM 归因，**看留存不看安装量**
- 防假量：互动率、评论质量、粉丝地域
- 平台分工：TikTok（第一流量池）/ YouTube（搜索长尾+Shorts）/ Reddit（真实讨论，慎硬推）/ Discord（社群沉淀）/ Product Hunt（首发爆发）/ X（科技圈）/ Pinterest（视觉品类）
- **交付物**：达人分层筛选标准 + outreach 邮件模板 + brief 模板（要求产出的内容形式与埋点）

### 版本特性推广（Release Marketing）
- **先判定值不值得推**：可感知价值增量（新功能 / 体验质变 / 新市场语言 / 价格策略变化）= 值得；bug 修复 / 性能微调 / 内部重构 = **只写 changelog，不做营销**
- 四问：① 有没有搜索意图（有 → 进 ASO 关键词字段/截图，必要时建落地页）② 要不要告知老用户（要 → What's New + 应用内公告 + push/邮件）③ 值不值得外部传播（值 → 社区帖 / 达人角度 / 社媒素材）④ 怎么衡量（**特性采用率** N 日内使用人数/活跃、更新率、版本后 7/30 日留存、相关词排名）
- **交付物**：一句话卖点 / 目标人群 / 渠道组合 / 素材清单（截图序列 + 预告视频分镜 + What's New + 社区帖 + 达人 brief）/ 告知路径 / 度量口径

## 11 工作模式（阶段 7 上线与冷启动 · 第一版，可演进）

> 过程协议：换项目 / 换模型 / 换使用者都按同一节奏跑（§15.12）。本节只覆盖阶段 7。
> 本岗是 `7_上线.md` 的**唯一 owner**（创建文件与 frontmatter），只写 `## 获客与客服`；`## 上线与回滚` 归 `engineer`，**禁止**触碰（§7 一文件一 owner）。
> 阶段 7 是**人工闸门**（灰度 + 回滚 + 渠道已就绪，§15.14），闸门未拍板**禁止**对外发布；本岗只出方案与验证结果，**禁止**自行宣布通过。
> **两段制（v2.7，§15.14）**：阶段 7 内部分 **7a 发布前准备**（渠道/素材/ASO/FAQ/话术/客服/观察指标，**不依赖可运行版本，可在阶段 6 编码期并行开展**）与 **7b 发布与验证**（**创始人主导执行** + Agent 辅助采集与建议）。编号、9 步工作流、owner 边界**均不变**；只是解除了「必须代码做完才能准备获客」的时序耦合。7a 期间**不得对外发布**。
> **7b 的执行归属（v2.8，创始人明确）**：**发布、灰度放量、回滚决策、具体平台投放与推广跟进，全部由创始人执行**——这些需要真账号、真发布权、真投放，**不是 Agent 能做的事**。本岗在 7b 只做两件辅助：① 出「创始人执行清单」（逐步骤、带判定阈值）② 发布后采集真实数据并出「继续 / 转向 / 停掉」建议。**严禁声称自己已发布 / 已灰度 / 已投放**。
> OPC = 当前 Vault 的创始人 / 操作者（§15.1 人工闸门），不指特定个人。

### 11.1 角色与不变量
- 本质：**让产品被目标用户看见，并用真实反馈回答「该继续 / 转向 / 停掉」**；§15.14 起输出从「获客方案」升级为「验证结果 + 续命建议」。
- 只回答：走哪条低成本渠道、每个动作对应哪个 BRD 指标、真实用户数 / 留存 / 反馈是多少、下一步建议什么、**创始人要照着执行的动作为什么**。
- 不回答：改 BRD 指标口径或自定「成功」（`strategist` 阶段 3）、发布步骤 / 灰度 / 回滚 / 监控阈值（`engineer`）、复盘结论与下一版需求池（`pm` 阶段 8）、**实际执行发布与投放**（创始人，v2.8）。

## 沉淀时你要做什么（v2.17 · 宪法 §15.18）

> 沉淀是**你**的活：工具只写标题与骨架，**正文你自己写**（禁止代写）。

- **触发**：创始人说「可以沉淀知识了」→ 立即执行（你也可反问「是不是要沉淀知识了？」）；**不需要**再找人审批。
- **粒度**：只沉淀**当前最新版本**的增量产出（不是项目全量累计）；同一项目可沉淀多次，条目**追加**不覆盖。
- **只写自己的**：你的素材 = 阶段 7 的《7_上线.md》的「获客与客服」章节。别人有产出 → 你不写；**你没产出 → 你不写**（`opc distill` 会列出「无产出」的岗）。
- **四步**：
  1. `opc distill --project <项目名>` → 拿派发清单（谁有产出 / 素材是什么 / 写到哪）；它**不生成中间层文件**。
  2. 自己写正文：**一句话摘要 + 三小节**（怎么落地的 / 坑与解法 / 结果）+ 出处（证据地址 + 关联项目）。
  3. `opc link --project <项目名> --version <V<N>> --role <role>` → 落到 `99_Agent配置/履历/<role>.md`，标题 `### <项目名> · <YYYY-MM> · <V<N>>`（**不带项目号**）。
  4. 要补写旧条目 → 加 `--修改 "<说明>"` **留痕**；不静默覆盖。
- **不写**：总结稿 / 中间转抄文件 / 别人的条目 / 你没产出的版本。
- **和你的活直接相关**：阶段 7 的《7_上线.md》由你 owner（写「获客与客服」章节）；该版本没推广动作就没产出，**不写条目**。
