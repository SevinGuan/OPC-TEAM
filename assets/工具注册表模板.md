# 工具注册表

> 全局唯一真相源（§15.11）。**Agent 只读**；新增与变更只能由创始人经 `opc tools promote --approve` 写入。
> 本表只存元信息与**凭证环境变量名**，**绝不存 API Key 值**；MCP server 的实际配置留在宿主，不进 Vault。
> 状态：`候选`（已登记未启用）→ `生效`（允许调用）→ `废弃`（原地标注，禁止删除）。
> 三级演进：项目临时 `_工具配置.md` → 本表登记 → 岗位卡 §10 预置（需 §9 升格 + 创始人确认 + 版本 +0.1）。
> 工具权限**不得越过 §8 scope**；出厂预置默认保留 `scope: Propose`，实际调用仍受本岗 §8 与 §14 自检约束。

## 首批出厂预置（2026-11-12 核实）

下列 22 项经联网核实来源 / 许可 / 维护状态，并由创始人批量确认，列为 `status: 生效`、`preset: true`。
新项目 `opc new` 会把当时的 `registry_version` 快照进项目层并钉扎；后续注册表升级不影响在跑项目。
**风险已显式标注**，企业级落地前请复核：官方参考集内 GitHub / PostgreSQL 等 12 个 server 已归档（改用第一方）；
Gitleaks 进入维护模式；Semgrep 规则集与引擎许可不同；Metabase / Plausible / Grafana 为 AGPL 故未纳入首批预置；
SerpApi 与 Figma 为专有服务（结果按 §12 当不可信输入）；部分第一方 MCP 只核实了维护方与活跃度，许可文本标为「见仓库 LICENSE」，启用前须复核。未找到可靠工具的能力槽位保留「待补」，不硬凑。

## 能力槽位（稳定，工具可换）

岗位卡 §10 只引用槽位与当前 `tool-id`；换工具时只改本表的映射，岗位卡不动。

| 职业 | 能力槽位 |
|---|---|
| `strategist` | 经营约束校验、立项决策记录、商业可行性测算、竞品与市场格局、复盘指标、商业模式画布、指标口径、定价与单位经济、财务测算、合同与合规 |
| `market` | 行业信号采集、竞品情报、用户痛点与访谈、问卷与行为数据、可视化与作图、素材归档 |
| `pm` | 需求拆分、用户故事与流程图、原型与交互、验收用例、迭代记录 |
| `design` | 设计系统、界面出图、原型与交互、可访问性走查、设计引导与资源库（fantasy-web-design，**随包预置**）、素材生成 |
| `engineer` | 代码检索、测试与覆盖率、部署与回滚、日志与监控 |
| `architect` | 规格先行（OpenSpec）、执行纪律（Superpowers）、时序图、API 契约生成、架构决策记录 |
| `growth` | 渠道投放、素材与文案、数据看板、客服话术、活动规则 |
| `governance` | 红线扫描、版本与索引审计、评测集、凭证合规、归档检查 |
