# 岗位会话实操（Agent 亲自跑某一棒时）

> 宪法管「必须做什么」，本文件管「怎么做才不返工」。细则按需读；引用的章节号以 `references/OPC-架构规范.md` 为准。

## 1. 标准序列（每一棒都走这五步，顺序不能换）

| 步 | 动作 | 命令 | 完成判据 |
|---|---|---|---|
| 1 | 领活（pull 式，自己领） | `opc claim --role <role> --project <项目号>` | 交接状态里本岗 `status=进行中` |
| 2 | 生成**自己那一份**骨架 | `opc scaffold --role <role> --project <项目号>` | 版本目录下出现 `<role>/` 与自己的主产出 |
| 3 | 填内容 → 按岗位卡 §8 自检 | `opc resolve <role> <逻辑键> --project <项目号>` 取 `artifact_uri` | frontmatter `status` 改完成、`source` 指向真实上游 |
| 4 | 报完成（自动出快照 + 通知 + 门铃） | `opc done --role <role> --project <项目号>` | 打印资产批次号与回执 token |
| 5 | 推进 | 创始人拍板后 `opc go --decision <结论>` | 游标前移、下一棒被叫醒 |

**`scaffold` 一次生成本岗该版本索引里登记的全部资产**（strategist = 约束卡 / 立项决策 / BRD 三份）。只填本次这一棒对应的那一份，其余保持 `status: 草稿` —— 草稿不算产出、不进沉淀清单、不进台账「产出份数」。

## 2. 对创始人说话：显示名 vs 短 ID

| 场合 | 写什么 |
|---|---|
| 聊天汇报、约束卡/台账/履历标题 | **项目显示名**（如「可爱的奶龙」）+ 版本号（`V1`） |
| 命令参数、产出索引末列 `ID`、交接状态文件名 | **短 ID**（`P001`） |

短 ID 出现在人读处会被当成「项目改名了 / 口径漂移」。宪法 §15.8 / §15.18.5 已定「人读处一律不带 P00X」，汇报时别自己加回去。

## 3. 闸门拍板：留痕与拿结论是两件事

| 动作 | 作用 | 注意 |
|---|---|---|
| `opc ask --role <role> --project <项目号> --text "..."` | 用本岗身份在群里 @ 创始人（红点提醒）+ 落 `_交互留痕.md` | 只负责**把问题送出去**，不产生结论、不推进游标 |
| 选择题（带选项、推荐项排第一、一次只问一个问题） | **拿到明确结论** | 创始人的回复可能是「继续推进」「同意」「可以」这类模糊话 —— 那不是结论，不构成「通过」 |
| `opc go --decision 通过\|驳回\|需补充 --basis "<依据>"` | 落盘拍板留痕 + 推进 | 闸门（阶段 0/2/7）必须带明确结论；「继续」不算闸门结论 |

- **闸门阶段收到的「继续推进」必须再问一次**才有结论；非闸门阶段「继续」才可直接 `go`。
- 派多个相关决定时**合并成一次提问**（一次只问一个问题，但多个决定可在同一轮内给出），创始人按选项回比让他写自由文本快且不会歧义。
- `--basis` 写**创始人实际说的话**（可引原话），供事后审计查「这棒是不是创始人放行的」。

## 4. 减法：精简 vs 跳过

- **精简（安全）**：同一岗位少做几件事 —— 少跑一轮调研、只做 Pre-MVP 不做全量竞品、短 MRD、单一渠道。表现为**同岗产出变薄**，不动交接链。
- **跳过（要先验算）**：少一个岗位 = 交接链少一棒。跳过前查两处依赖：
  1. **跨岗输入契约**：被派的下游岗位的岗位卡 §4「输入契约」里，若列了被跳过岗位的产出 → **跳不掉**，该下游会按契约硬停。
  2. **同岗连续阶段**：本岗自己下一阶段的输入契约是否含被跳过阶段的产出 → 例如阶段 3 的输入契约要求「阶段 2 已拍板 Go 的立项决策」→ 同岗两阶段不能只留一段。

**判定口径**：跳过某岗的充要条件 = 本次被派的全部下游岗位，输入契约里都不含它的产出；否则只能压深度、不能删棒。创始人问「能不能跳过 X」时，先核契约再答，别先答应再在下游卡住。

## 5. 落盘与版本控制

- **`opc done` 之后不要再改本岗产出文件**：资产快照已登记当时的 SHA256，再改会被 governance 判为「未登记的静默修改」。要补充的内容，写进**下一棒的输入契约字段**（如约束卡的钉扎字段），并在汇报里点明「本次对已入库产出有追加、差异原因是什么」。
- **`opc done` 打印的 git hash 不等于已入库的证明**：先核它包含本次文件（`git log -1 --name-only` / `git show --stat <hash>`）。Vault 落在上级仓库的忽略范围内时，脚本会拿到上一条提交的旧 hash。核不过就如实说「本地已落盘、git 未入库」，不要拿 hash 当凭据。
- 修法二选一：Vault 目录内自建独立 git 仓库；或在上级仓库用 `git add -f` 强制纳入。两者都不影响流程 —— 资产快照机制独立于 git。
- 自查：`opc assets --role <role>` 看本岗各批次的指纹与时间。

## 6. 报错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `resolve` 报「未定义产出键 0_约束卡.md；可选：0_约束卡, …」 | 传了**文件名**，脚本要的是**逻辑键** | 去掉 `.md` 后缀：`opc resolve strategist 0_约束卡 --project <项目号>` |
| `triage` 提示「已建项，交接链不会因本次清单变更而改变」 | 交接链在建项那一刻定死 | 已产出的棒不动；只补后续需人工改交接状态（须创始人确认），或重建项目 |
| `go` 报「阶段 N 是人工闸门，请给出结论」 | 闸门必须带结论 | 补 `--decision` |
| `go` 报「不是人工闸门」 | 非闸门棒不接受 `--decision 通过` | 直接 `go`；要退回重做用 `--decision 驳回\|需补充` |
| `done` 报「主产出未落盘」 | 没 scaffold，或文件不在版本目录的 `<role>/` 下 | 先 `opc scaffold --role <role>`，再确认 `artifact_uri` 与实际路径一致 |
| `done` 报「跨步被拒绝 / 未被派活」 | 本岗不在本次交接链上 | 不要硬报完成；让 pm 用 `opc triage` 补派，或核对交接链 |

## 7. 一次会话只能跑一个 role 的一段

- 同一岗位承担多个阶段时，**按岗位卡的 §11 / §12 / §13… 分次会话，每次只加载对应那一节**；阶段 0→2→3 之间的闸门不因同岗而省略。
- 一个会话内**不要顺手替下一棒产出内容**：交接只走文件，Agent 之间不互相唤醒（宪法 §15.3）。
- 阶段 8 收尾时另有一条并行链：本岗追加自己职业简历的 C 节条目（正文自己写，工具只落骨架）。
