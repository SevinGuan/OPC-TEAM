新建一个 OPC 项目。

**脚本**：`<skill包目录>/scripts/opc.py <子命令>`（`<skill包目录>` = 本 Skill 包所在目录，与宿主无关）。定位顺序：① 环境变量 `OPC_SKILL_DIR`；② 宿主注入的 skill 目录变量（指向包目录本身或其父目录）；③ 目录结构约定：`<本命令文件所在目录>/../../skills/opc-team/`（多数宿主把 `commands/` 与 `skills/` 放在同一配置根下）；④ 在工作区与用户主目录搜 `opc-team/scripts/opc.py`。用宿主可用的 Python 解释器以绝对路径调用。

**步骤**

1. 项目名缺失时询问；名称不能为空。
2. 类型标签：从当前 profile 的 `tags_vocab` 让用户选 2–4 个（可新增），拼成 `--tags "#A #B"`。
3. 派活清单是路由的唯一真相源：**优先用 `/opc:triage` 起草**（结构化，落 `<项目目录>/_派活清单.json`），再把该文件路径作为 `--triage <清单文件>` 传入；不要再传 `--scope`（它只是标签）。
   - 清单也可用手写的 `4_产品基线.md`（含「本次涉及岗位与产出资产清单」小节）。
   - **解析失败会报错并中止建项**（找不到小节 / 无一行判出「涉及」/ 判定词不认识 / 岗位名未登记）——**不要改用不带 `--triage` 重试**，那会按全量 9 步派活。先按报错把清单改对。
   - 完全不给 `--triage` 也能建，但**必须明确告知用户这次按全量 9 步派活**。
4. 执行 `new`，把输出的相似项目清单与落地物 URI 汇报给用户。
5. 新建后执行 `status --vault <vault>`，确认当前项目已写入 `opc.config.json`。

**版本语义（v2.17）**：**创建项目 = 第一次立项 = V1** —— 脚本会自动在项目目录写一份 `_版本台账.md`（V1 行），交接状态的当前版本记为 `V1`。项目目录名是 `项目名`（**不带 `P00X_` 前缀、不带日期**；同名加 `-2`），短 ID 只出现在索引末列与状态文件名里。项目里后续再确认新需求 → 用 `/opc:version`。

**产出语义（v2.18 / v2.19）**：建项**只登记不产文件** —— 写版本台账行 + 产出索引行 + 交接链，**不预生成任何产出空壳**。岗位真正开工时用 `/opc:scaffold` 生成自己那一份（落 `YYYY-MM-DD-V<N>/<role>/`）；没干活的职业，在该版本下连目录都不存在。

**完成标准**：项目目录已建（含 `YYYY-MM-DD-V1/` 版本目录与 `_版本台账.md`），`30_项目/_产出索引.md` 出现该项目行，相似项目检索结果已汇报。

**深入**：派活规则 → `references/命令与配置手册.md` §29、§38；版本链 → 手册 §42、规范 §15.18；产出按需生成 → 手册 §43、规范 §15.19；相似检索判据 → 规范 §15.7。
