pm 的多项目统筹台账。

**脚本**：`<skill包目录>/scripts/opc.py <子命令>`（`<skill包目录>` = 本 Skill 包所在目录，与宿主无关）。定位顺序：① 环境变量 `OPC_SKILL_DIR`；② 宿主注入的 skill 目录变量（指向包目录本身或其父目录）；③ 目录结构约定：`<本命令文件所在目录>/../../skills/opc-team/`（多数宿主把 `commands/` 与 `skills/` 放在同一配置根下）；④ 在工作区与用户主目录搜 `opc-team/scripts/opc.py`。用宿主可用的 Python 解释器以绝对路径调用。

**步骤**

1. 执行 `pm`（只读，不改任何状态）。
2. 汇报四张清单：各项目阶段与接手岗位、待 pm 推进、待创始人拍闸门、未上送（同步队列积压）。
3. 跨项目同一 role 占用冲突要显性列出，并**只提排期建议，不替创始人定优先级**。
4. 汇报**「现在该派谁」**面板（接手岗位 × 岗位占用 × 闸门状态 → 可接 / 进行中 / 排队 / 冲突 / 等创始人拍板 / 待 pm 推进）与各项目**派活清单状态**。

**完成标准**：四张清单齐全且与索引一致；冲突项已点名；派活结论逐项目给出，并给出可执行的下一步命令（起草派活清单用 `/opc:triage`）。

**深入**：统筹范围 → 规范 §15.15；`advance` → 手册 §34；派活入口 → 手册 §38。
