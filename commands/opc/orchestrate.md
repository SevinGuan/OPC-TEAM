跑**一轮**外部编排器：读 Vault 里的交接状态，判断哪些棒可以自动推进，然后推进。

**脚本**：`<skill包目录>/scripts/orchestrator.py`（`<skill包目录>` = 本 Skill 包所在目录，与宿主无关）。定位顺序：① 环境变量 `OPC_SKILL_DIR`；② 宿主注入的 skill 目录变量；③ 目录结构约定：`<本命令文件所在目录>/../../skills/opc-team/`；④ 在工作区与用户主目录搜 `opc-team/scripts/orchestrator.py`。用宿主可用的 Python 解释器以绝对路径调用。

**它做什么 / 不做什么**（宪法 §15.3、§15 ④）

| 情形 | 编排器 |
|---|---|
| 某棒已报完成、**不在闸门** | **自动推进一棒**（替创始人说出那句「继续」；只一棒、不跳步） |
| 落在**人工闸门**（阶段 0 / 2 / 7） | 只推一条「待拍板」通知并**停下** —— **绝不代拍**，绝不写 `decision` |
| 某棒久无进展 | 只推提醒，不推进、不打断 |
| 产出内容 | **一个字都不改** |

交接仍走固定文件 + 通知通道，**不唤醒别的 Agent**（§15.3）；下一棒仍自己领活（`opc queue --role <role> --claim`）。

**步骤**

1. 先跑一次 `--dry-run --json`，把「它打算做什么」摊给用户看。
2. 用户认可 → 跑正式的一轮（`--once`）。
3. 向用户复述：推进了哪些项目、哪几棒；若有闸门待拍板，**把拍板命令一并给出**（`opc go --project PXXX --decision 通过`）。
4. 闸门**不要**替用户拍 —— 这是创始人独有的动作。

**常用参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--once` | — | 跑一轮就退出（本命令的默认行为） |
| `--dry-run` | 否 | 只报告不动作（不推进、不写任何文件） |
| `--min-wait` | 30 | 报完成后再等多少秒才推进（给创始人留喊停窗口） |
| `--remind` | 900 | 同一闸门 / 停滞的重复提醒间隔秒 |
| `--channel` | 配置里的 `notify.channel` | 通知通道 |
| `--project` | 全部 | 只处理指定项目 |
| `--json` | 否 | 机器可读输出 |

**完成标准**：`--once` 正常退出；输出的动作列表已向用户复述；若有闸门项，用户拿到拍板命令。
