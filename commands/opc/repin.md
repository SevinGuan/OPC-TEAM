把项目的**规则钉扎**（`pinned_refs`，规范 §10）迁到新的规范版本。

**脚本**：`<skill包目录>/scripts/opc.py repin`（`<skill包目录>` = 本 Skill 包所在目录，与宿主无关）。定位顺序：① 环境变量 `OPC_SKILL_DIR`；② 宿主注入的 skill 目录变量（指向包目录本身或其父目录）；③ 目录结构约定：`<本命令文件所在目录>/../../skills/opc-team/`（多数宿主把 `commands/` 与 `skills/` 放在同一配置根下）；④ 在工作区与用户主目录搜 `opc-team/scripts/opc.py`。用宿主可用的 Python 解释器以绝对路径调用。

**前提（规范 §10）**

> 解钉**必须**先做 §11 变更影响评估。

- **评估由人做，脚本只负责执行** —— 本命令不替代评估，也不做评估。
- 规范升版**不自动**改变在跑项目的依据；不重钉是合规状态，不是错误。

**步骤**

1. 先跑 `status`，看「规则钉扎」那行：哪些项目钉在旧版本。
2. 若确需重钉：**先做完 §11 变更影响评估**，把结论写进 `--reason`。
3. 执行 `repin --project <项目号> [--project <项目号> …] --reason "<评估结论>"`。
4. 向用户复述：哪些项目从哪个版本迁到哪个版本、留痕写在哪。
5. 复跑 `status`，确认「钉在旧规范版本」已归零。

**参数**

| 参数 | 说明 |
|---|---|
| `--project PXXX` | 项目号或项目全名，可多次；默认**只动点名的项目** |
| `--all` | 处理全部已钉扎项目（要动全部必须显式写出来） |
| `--to vX.Y` | 目标版本；默认 = Vault 内宪法实际版本 |
| `--reason "…"` | **必填** —— §11 评估结论，写进项目留痕；缺了脚本直接报错 |

**完成标准**：目标项目的 `0_约束卡.md` 里 `pinned_refs` 已指向目标版本，并留下 `repinned_from` / `repinned_at` / `repin_reason` 三行留痕。

**注意**：重钉只改「依据哪个版本」，**不改已产出的内容** —— 产出本身仍按原依据保留。
