把**一个版本**的产出沉淀进各职业的履历卡。

**脚本**：`<skill包目录>/scripts/opc.py distill [--status] [--project <项目名>] [--version <V<N>>]`（`<skill包目录>` = 本 Skill 包所在目录，与宿主无关）。定位顺序：① 环境变量 `OPC_SKILL_DIR`；② 宿主注入的 skill 目录变量（指向包目录本身或其父目录）；③ 目录结构约定：`<本命令文件所在目录>/../../skills/opc-team/`（多数宿主把 `commands/` 与 `skills/` 放在同一配置根下）；④ 在工作区与用户主目录搜 `opc-team/scripts/opc.py`。用宿主可用的 Python 解释器以绝对路径调用。

**何时触发**

- 用户说「**可以沉淀知识了**」「把这个的经验总结一下」→ **立即执行**，**不必再找谁审批**。
- 用户只是说「这版做得不错」而没提沉淀 → 你**可以反问**一句「是不是要沉淀知识了？」再动手。
- 用户问「哪些岗还没写履历」→ 走 `distill --status`（只读汇总）。

**步骤**

1. **确定项目与版本**：默认当前项目 + **最新版本**；用户点名了版本就带上 `--version`。项目标识接受**项目名 / 项目号 / 目录名**任意一种。
2. **`distill --project <项目>`** → 拿到**派发清单**：谁有实际产出、素材是哪些文件、写到哪。**不生成中间层总结稿**；版本状态 → 待沉淀。
3. **各职业自己写自己的**（这一步**只能由本职业做**，不代写）：
   - 你只写**你自己岗位**的条目。别人有产出 → 你不写；你这一版没产出 → 你不写。
   - 正文格式（**一句话摘要 + 三小节 + 出处**）：

     ```markdown
     ### <项目名> · <YYYY-MM> · <V<N>>
     > 一句话摘要：<一句话说清这次做了什么>
     - 怎么落地的：<步骤与关键取舍>
     - 坑与解法：<踩到的坑与解法>
     - 结果：<可验证的结果>
     - 证据：[[<产出地址>]]
     - 关联项目：<项目名> → [[30_项目/_产出索引#<项目名>]]
     ```

   - 落地：`opc link --project <项目> --version <V<N>> --role <role>` → 工具写好标题与骨架，**三小节由本职业自己补齐**（工具**禁止代写**）。
   - 要补写旧条目 → 加 `--修改 "<说明>"` → **留痕**写进条目，不静默覆盖。重复写同一条会被跳过。
4. **`distill --status --project <项目>`** → 汇总：谁写了 / 谁没写 / 谁没产出；齐了 → 版本状态 = **已沉淀**。没齐就把还差的岗列出来（**不要替他们写**）。

**要点（v2.17 · 规范 §15.18）**

- **粒度 = 当前最新版本的增量**，不是项目全量累计；同一项目可沉淀多次，条目**追加**不覆盖。
- **没实际产出 = 不写**：`status: 草稿` 的占位空壳**不算产出**（派发清单会把它列在「无产出」里）。
- **不建中间层**：不写总结稿再让各岗转抄 —— 派发清单直接派到岗。
- **人读处不带 `P00X`**：条目标题是 `### <项目名> · <YYYY-MM> · <V<N>>`。

**完成标准**：派发清单已发出（有产出的岗都知道该写什么）、本岗条目已落地、汇总显示该版本已沉淀或明确列出还差谁。
